# QQ GIF 表情：配置、协议与验收

本功能属于固定 Hermes 基线的源码 overlay，不是单独复制即可安装的插件。先完成[部署步骤](DEPLOYMENT.md)，再按[验证账本](VERIFICATION.md)区分离线回归与实际 QQ 送达。仓库不包含私人图库或可直接启用的部署配置。

## 两种模式

- `expression`：主模型在组织回答时选取已审核 ID。辅助选图器不接管决定；发送事实在后续模型请求中回注，选中不等于已发。支持纯 GIF，也支持先文字、再独立纯 GIF。
- `auto`：保留兼容的后台选图路径，仅在正文实际确认发送后考虑追加。该路径需要显式的 `auxiliary.qq_meme_select` DeepSeek 路由，可能产生额外请求和费用，不支持自动换提供方。不是主模型自主表达模式。

源码兼容默认模式为 `auto`，功能默认关闭。若希望主模型自行决定，必须显式配置 `mode: expression`。不要仅凭安装了新模块就断言已经切换。

## 最小配置

[安全示例](../examples/config.safe.yaml)保持平台和表情均关闭，受众为空。启用前由操作者私下填写：

- `platforms.qqbot.extra.memes.enabled`：显式 `true` 才启用。
- `mode`：`expression` 或 `auto`。
- `root_dir`：操作者准备的本地 GIF 根目录，必须是绝对本地路径。
- `catalog_path`：目录 JSON 的绝对本地路径；省略时读取所属 Hermes home 下的 `qqbot/memes/catalog.json`。
- `groups` / `dm_users`：显式完整平台 ID 列表。`all_groups: true` 会覆盖当前及未来接入的普通群回复，须另行知情启用；它不开放其他私聊，也不授予管理员权限。
- `intimacy_users`：仅用于确实审核为 `intimate_dm` 的条目，不等于后台管理员名单。条目的适用受众由图库审核决定，不按图名自动猜测。

源码设置默认值：`probability: 0.2`、`cooldown_seconds: 180`、`recent_exclude: 3`、`max_per_chat_per_day: 30`、`min_confidence: 0.75`、`selector_timeout_seconds: 6`。这些是源码默认，不是私人部署的调参结果。`probability: 0` 硬性关闭选图；每日上限 `0` 表示不设该上限，正数 1–100 按滚动 24 小时限制。

`expression` 按解析后是否有正文分流，不按标记拼写分流：带正文的附图统一经过持久化 PRD；无正文的单张 GIF（含 optional-only、空白正文）跳过概率、装饰冷却与最近图片排除。两种形式均保留权限、硬关闭、每日额度、同事件防重发、并发保护和文件校验。PRD 不是每次独立等概率投硬币，不保证短窗口固定比例。

## 准备自己的审核目录

使用 UTF-8 JSON：顶层 `schema_version: 1` 与 `items` 数组。每条必须含：

- `id`：1–64 位小写字母/数字/下划线/连字符，首字符为字母或数字，全目录唯一。
- `relative_path`：根目录下的 GIF 相对路径，不得含绝对路径、回退、反斜杠或盘符。
- `sha256`：实际文件字节的 64 位小写 SHA256；替换文件后须重新审核并更新。
- `description`：非空语义描述；`use_when`、`avoid_when`：非空字符串列表。
- `audiences`：由 `group`、`dm`、`intimate_dm` 组成的非空列表。
- `enabled`、`reviewed`：显式布尔值，均为 true 才可使用。

目录最多 200 项、256 KiB；每张最多 10 MiB，须带有效 GIF87a/GIF89a 文件头。审核描述会成为模型上下文，不应包含凭据、私人路径或恶意提示。仅把文件放入目录不代表获批。expression 使用全部合格审核条目；旧 auto 选择器的候选列表最多 20 项。

不提供假摘要或假审核图库。请使用有权使用和传播的 GIF，自行核对内容、受众及许可后填写真实摘要。

## 主模型控制协议

模型应在最后唯一独立行给出一个结论：

- `[[qq_meme:完整ID]]`：明确请求这张 GIF，可不带正文。
- `[[qq_meme_optional:完整ID]]`：允许附图抽取；也支持无正文的纯 GIF。两种选图标记有正文时均抽取，正文不能承诺一定发图。
- `[[qq_meme_none]]`：本轮判断过、不配图，不建立发送意图。

解析后控制标记不出现在正文。代码/引用中的示例不是发送指令；坏标记、重复或半截标记不应获得发送权限。缺结论记录日志但不阻断正文。能力说明倾向于每轮考虑表情，并不代表所有场景都必须发图。公开文案遵循实际审核目录，未沿用私人部署的“可爱风／所有语境均已批准”断言；图库语义提示不能代替代码授权。

## 每轮候选与软多样性

每个新事件提供当前候选的 ID、语义、`use_when` 及 `recent_sent_count`；仅统计所属 profile/transport/chat 最近最多 50 次成功发送。0 不代表历史从未使用；意图、概率未中、失败和 unknown 不计入。多图同样贴切时可偏好较少使用者，常用图仍可选，后台不轮播、不替换主模型所选 ID、不改概率。

附图与纯 GIF 分别提供可用性和候选。重复准备同一事件复用不可变候选快照，但已发生的发送事实仍实时读取。插件发现/重载后，已连接适配器固定使用同代的标记类型、表达引擎和回执 ContextVar，避免静默失去原生队列 stamp。

## 发送、持久化与失败

模型只知道审核 ID 和语义，不选择任意路径或收件人。执行层校验精确字节，创建单次快照，只授权当前请求、profile、transport、chat 对应的快照；随后经原生媒体路径发送并清理。普通流式文字不能泄露控制标签，也不能绕开本轮表达处理。

有正文时先取得真实文字回执，再单独发送无 content/markdown/caption 的 GIF；纯 GIF 不要求先发占位文字。纯 GIF 被拦截或结果未知时不自动补发“发送失败”等文字，真实状态仍保留在本地。正文失败不能靠 GIF 伪装整轮成功，GIF 失败也不应吞掉已发送正文。

意图、尝试和真实回执分别记录；`selected`、`attempting`、`unknown` 均不是 `sent`。超时、取消、缺有效平台 ID、结果写回故障不应触发整轮重发。重入、持久队列与 queued final 必须共享同一发送负责人；压缩延续可继承受同一来源绑定的发送事实，`/new`、reset 和分支不得借用其他会话事实。

本地表达状态位于所属 home 的 QQ 缓存数据库。记录用于去重与发送事实，不是无限聊天历史；图库损坏或停用不应让模型忘记已经确认的发送。

## 数据流与验收

expression 会把目录描述、当轮可用性和相关发送事实提供给配置的主模型；GIF 字节发送给 QQ 及目标受众。auto 还会把当前输入、回复片段和候选描述发给显式选图提供方。模型服务和 QQ 各自的费用、存储政策适用；默认关闭不代表主聊天服务也停止数据传输。

按以下层次验收，不相互替代：

1. 固定干净宿主应用补丁，核验完整 overlay 与 manifest 一致。
2. 离线回归覆盖解析、审核/摘要、频控、权限、故障/重入、持久原生队列、压缩/回放与正文/GIF 边界。
3. 不连接 QQ 的真实模型探针只能证明选图语义，不能制造 sent 回执。
4. 操作者手动载入后，在明确同意的测试目标验证真实回执、客户端动画、纯 GIF 无占位提示，以及下一轮模型知道刚才发了哪张。

本次仓库同步不自动启用功能、不改变现用图库、不重启服务，也不向真实群发送测试消息。具体实际测试范围以[验证账本](VERIFICATION.md)为准。
